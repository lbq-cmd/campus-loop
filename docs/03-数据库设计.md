# 数据库设计说明书

**数据库**：SQLite 3
**初始化脚本**：[`sql/schema.sql`](../sql/schema.sql)（结构）+ [`sql/seed.sql`](../sql/seed.sql)（默认分类）
**存储位置**：默认 `data/campusloop.db`，可通过 `-Dcampusloop.db.url` 指定
**版本**：v1.2（迭代二落地 4 张核心表，其余 4 张表为迭代三预留）

---

## 1. 设计原则

1. **单文件零安装**：SQLite 内嵌于应用，无需数据库服务，符合"桌面系统直接部署"要求；
2. **约束前置**：能用数据库约束表达的规则（唯一、外键、CHECK）绝不只靠代码，形成最后一道防线；
3. **逻辑删除**：物品违规下架使用 `REMOVED` 状态而非 `DELETE`，保留流转与审计线索；
4. **可审计**：关键操作写 `operation_logs`（迭代三接入查询界面）；
5. **避免冗余**：物品标签使用逗号分隔文本（单值场景，量小），不单独建表；分类为独立表以支持管理员维护；
6. **时间统一 ISO-8601 文本**：SQLite 无日期类型，`LocalDateTime.toString()` 存储，字典序即时间序。

## 2. 实体关系概览

```text
users 1 ──── * items          （发布：一个用户可发布多个物品，删除用户级联删除其物品）
categories 1 ──── * items     （归类：分类被删除前需先处理物品，外键默认 RESTRICT）
users * ──── * items          （收藏：通过 favorites 关联，复合主键防重复）
items 1 ──── * trade_requests （意向沟通）
trade_requests 1 ──── 1 trade_records （成交记录）
trade_records 1 ──── * reviews（双向评价）
users 1 ──── * operation_logs （操作审计）
```

## 3. 表结构

### 3.1 users 用户表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTOINCREMENT | 用户主键 |
| username | TEXT | NOT NULL UNIQUE | 登录名，4-20 位字母开头 |
| password_hash | TEXT | NOT NULL | PBKDF2 密文，格式 `pbkdf2$iter$salt$hash` |
| nickname | TEXT | NOT NULL | 昵称，2-20 字 |
| contact | TEXT | 可空 | 联系方式 ≤40 字 |
| role | TEXT | NOT NULL CHECK IN ('STUDENT','ADMIN') | 角色 |
| status | TEXT | NOT NULL CHECK IN ('ACTIVE','BANNED') | 账号状态，默认 ACTIVE |
| credit_score | INTEGER | NOT NULL DEFAULT 100 CHECK 0..150 | 信用分 |
| created_at | TEXT | NOT NULL | 注册时间 |
| last_login_at | TEXT | 可空 | 最后登录时间 |

### 3.2 categories 分类表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTOINCREMENT | 分类主键 |
| name | TEXT | NOT NULL UNIQUE | 分类名 |
| description | TEXT | 可空 | 分类说明 |
| sort_order | INTEGER | NOT NULL DEFAULT 0 | 展示顺序（小在前） |

默认数据：教材书籍、数码配件、文体用品、生活物资、代步工具、其他闲置（`seed.sql`，`INSERT OR IGNORE` 可重复执行）。

### 3.3 items 物品表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTOINCREMENT | 物品主键 |
| owner_id | INTEGER | NOT NULL FK users(id) ON DELETE CASCADE | 发布者 |
| category_id | INTEGER | NOT NULL FK categories(id) | 分类 |
| title | TEXT | NOT NULL | 标题 2-60 字 |
| description | TEXT | 可空 | 描述 ≤500 字 |
| item_type | TEXT | NOT NULL CHECK IN ('SELL','EXCHANGE','FREE') | 流转方式 |
| price | REAL | NOT NULL DEFAULT 0 CHECK ≥0 | 价格；交换/赠送恒为 0 |
| item_condition | TEXT | NOT NULL CHECK IN ('NEW','LIKE_NEW','GOOD','FAIR') | 成色 |
| status | TEXT | NOT NULL CHECK IN ('ONLINE','OFF_SHELF','LOCKED','SOLD','REMOVED') | 状态 |
| tags | TEXT | 可空 | 逗号分隔标签，≤5 个 |
| image_path | TEXT | 可空 | 图片本地路径（迭代四图片存储使用） |
| view_count | INTEGER | NOT NULL DEFAULT 0 | 浏览量 |
| created_at | TEXT | NOT NULL | 发布时间 |
| updated_at | TEXT | NOT NULL | 最后修改时间 |

索引：`idx_items_owner(owner_id)`、`idx_items_category(category_id)`、`idx_items_status(status)`，
覆盖"我的发布""分类筛选""在架商品"三类高频查询。

### 3.4 favorites 收藏表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| user_id | INTEGER | NOT NULL FK users(id) ON DELETE CASCADE | 收藏人 |
| item_id | INTEGER | NOT NULL FK items(id) ON DELETE CASCADE | 被收藏物品 |
| created_at | TEXT | NOT NULL | 收藏时间 |

主键：`(user_id, item_id)` 复合主键，天然防止重复收藏，配合 `INSERT OR IGNORE` 实现幂等。

### 3.5 ~ 3.8 迭代三预留表

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| trade_requests | item_id, requester_id, message, status(PENDING/ACCEPTED/REJECTED/CANCELED), created_at | 意向沟通 |
| trade_records | item_id, request_id, seller_id, buyer_id, final_price, carbon_saved, finished_at | 成交/交换流水与减排估算 |
| reviews | trade_id, reviewer_id, reviewee_id, score(1..5), comment, created_at | 双向评价，驱动信用分 |
| operation_logs | user_id, action, detail, created_at | 登录、发布、下架、封禁等关键操作审计 |

## 4. 关键约束与业务规则的对应

| 业务规则 | 数据库落点 | 代码落点 |
| --- | --- | --- |
| 用户名唯一 | `users.username UNIQUE` | `register` 先查重，捕获唯一约束再提示 |
| 角色/状态合法 | `role`、`status` CHECK | 枚举类型 + `valueOf` |
| 信用分区间 | `credit_score CHECK 0..150` | `adjustCredit` 截断 |
| 价格非负 | `items.price CHECK ≥0` | 服务层按流转方式校验（出售>0、交换/赠送=0、上限 10 万） |
| 物品必须归属真实用户/分类 | 外键 | 发布前查用户与分类 |
| 删除用户清理其物品与收藏 | `ON DELETE CASCADE` | — |
| 防止重复收藏 | 复合主键 | `INSERT OR IGNORE` + 返回影响行数 |
| 默认只看在架物品 | — | 查询默认 `status = 'ONLINE'` |

## 5. 初始化与使用

```sql
-- 建表（幂等，可重复执行）
sqlite3 data/campusloop.db < sql/schema.sql
-- 写入默认分类（幂等）
sqlite3 data/campusloop.db < sql/seed.sql
```

程序启动时 `SchemaLoader` 会自动执行上述脚本并创建 `data/` 目录，因此用户无需手工建库。
测试环境通过 `TestDb` 在临时目录生成独立数据库并执行同一份脚本，保证"测试结构 = 交付结构"。

## 6. 典型查询

```sql
-- 在架物品按关键词 + 分类 + 价格区间检索（对应 JdbcItemDao.search）
SELECT id, owner_id, category_id, title, description, item_type, price,
       item_condition, status, tags, image_path, view_count, created_at, updated_at
FROM items
WHERE status = 'ONLINE'
  AND category_id = ?
  AND price BETWEEN ? AND ?
  AND (title LIKE ? ESCAPE '\' OR description LIKE ? ESCAPE '\' OR tags LIKE ? ESCAPE '\')
ORDER BY created_at DESC, id DESC
LIMIT ?;

-- 我的收藏（对应 JdbcFavoriteDao.findItemIdsByUser）
SELECT item_id FROM favorites WHERE user_id = ? ORDER BY created_at DESC;

-- 用户发布数量统计
SELECT COUNT(*) FROM items WHERE owner_id = ?;
```

## 7. 备份与迁移

- 备份：停止程序后复制 `data/campusloop.db` 单文件即可；迭代四将提供界面"备份/恢复"按钮；
- 迁移：表结构由脚本集中管理，升级时按版本追加 `ALTER TABLE` 脚本；
- 跨库迁移：因全部 SQL 为标准 SQL + 预编译，迁移到 MySQL 仅需调整自增语法与外键类型。
