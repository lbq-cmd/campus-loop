## 4. 协作方式

### 4.1 版本管理

- 仓库：Git（Gitee/GitHub 私有库），主分支 `main`，开发分支 `iter2-dev`，功能分支 `feat/<模块>`；
- 提交信息规范：`<type>(<scope>): <subject>`，如 `feat(item): 支持按价格区间检索`、`fix(dao): 修正 SQLite 自增主键读取`；
- 合并前必须本地跑通 `mvn clean test`，由另一名成员 Review 后合并；
- 每周提交不少于 3 次，每人代码行数与提交次数纳入分工说明截图（提交前补）。

### 4.2 接口约定（迭代一确定，迭代二遵守）

1. 表现层不出现 SQL 与 JDBC 代码；
2. 业务层方法签名以 `domain` 实体 / `service.dto` 为参数与返回值，不返回 `ResultSet`；
3. 新增业务规则先在服务层加校验与测试，再考虑数据库约束兜底；
4. 公共工具类只增不改签名，避免影响他人分支。
